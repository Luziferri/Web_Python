Base de Dados — Minecraft2D

O projeto usa SQLite via sqlite3 (Python puro, sem ORM). O ficheiro está em models/minecraft2d.sqlite. A classe Database (models/database.py) é o data access layer que faz todas as queries.
Tabelas (6 no total)

1. users
Campos: id, username, email, password_hash, wood, stone, iron, diamonds, has_axe, axe_level, skin, created_at
- O que é: Conta dos jogadores.
- Interações: Criada no /register (auth.py), lida/atualizada em cada ação de jogo (cortar madeira, minerar pedra, construir, recolher recompensas, minerar diamantes). O password_hash usa pbkdf2_sha256 (passlib). has_axe/axe_level são para o machado da Mesa de Trabalho. diamonds é obtido como recompensa da Mineradora de Diamantes.

2. building_slots
Campos: id, user_id (FK→users), slot_number (1-4), building_type, state, action_type, started_at, ready_at, created_at

- O que é: 4 slots de construção por jogador. Cada slot tem uma máquina de estados: 
empty → building → ready → working → collectable → ready.

- Interações: Criados automaticamente no registo. Atualizados nas rotas /api/build, /api/task/start, /api/task/collect (game.py). Permitem construções e tarefas temporizadas sem cron jobs (compara ready_at com o relógio do servidor).

3. action_logs
Campos: id, user_id (FK→users), message, created_at
- O que é: Histórico de ações de cada jogador (ex: "Árvore cortada: +4 madeira").
- Interações: Inserido em cada ação de jogo (cortar, minerar, construir, etc.). Mostrado na dashboard (últimas 8 ações).

4. trees
Campos: id, column (2, 7, 13 — posições no mapa), chopped_at, removed_at, created_at
- O que é: Árvores no mapa, com sistema de cooldown de 10s (RESOURCE_RESPAWN_SECONDS).
- Interações: Lidas/atualizadas na rota /api/chop. Se chopped_at já passou do cooldown, a árvore fica disponível novamente.

5. stones
Campos: id, column (1, 4, 7, 10 — posições no mapa), mined_at, removed_at, created_at
- O que é: Pedras no mapa, mesmo sistema de cooldown das árvores.
- Interações: Lidas/atualizadas na rota /api/mine-stone. Lógica idêntica às árvores.

6. buildings
Campos: key (PK), name, cost_wood, cost_stone, cost_iron, construction_seconds, task_name, task_seconds, reward_wood, reward_stone, reward_iron, reward_diamond, description

- O que é: Catálogo de construções disponíveis (dados estáticos seedados na criação da BD). 3 edifícios:
- cabana → Mesa de Trabalho (fabrica/upgrade do machado)
- mina → Fornalha (funde minério → ferro)
- forja → Mineradora de Diamantes (extrai diamantes; custo: 10 madeira + 10 pedra + 20 ferro; constrói em 30s; tarefa: 30s; recompensa: 1 diamante)
- Interações: Lido ao mostrar a dashboard e ao validar construções/tarefas. Nunca é escrito durante o jogo.
Interações principais (fluxo de dados)

Registo → INSERT users + 4 building_slots 'empty' + action_log
Login   → SELECT users (valida password)
Dashboard → SELECT users + building_slots + action_logs + trees + stones + buildings
Cortar árvore → UPDATE trees (chopped_at) + UPDATE users (wood+4) + INSERT action_log
Minerar pedra → UPDATE stones (mined_at) + UPDATE users (stone+2) + INSERT action_log
Construir      → UPDATE users (deduz custo madeira/pedra/ferro) + UPDATE slot (estado 'building', ready_at calculado)
Recolher tarefa → UPDATE users (soma recompensa: madeira, pedra, ferro ou diamante; ou dá machado) + UPDATE slot (volta a 'ready')
Minerar diamante → Recolher tarefa da Mineradora de Diamantes (forja) → UPDATE users (diamonds+1) + INSERT action_log
Leaderboard    → SELECT users ORDER BY (wood+stone+iron+diamonds) DESC LIMIT 10

Todas as queries usam ? como placeholder (protegido contra SQL injection). 

As ligações são abertas com connection.row_factory = sqlite3.Row para aceder a colunas por nome.
